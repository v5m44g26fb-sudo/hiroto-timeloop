## 2. 流用できないもの（作り替え）

- **Tinderアプリ本体**: 本作に出会い系・マッチング要素はない。丸ごと削除し、代わりに「番組アプリ」（名簿・順位・投票・ミッション表示、下記 §4-0）が本作の中心アプリになる。**番組アプリは新規開発ではなく裏側3部作からの流用**（本人の指摘で確定、2026-11-09。詳細は §4-0）
- 物語データ全般（会話文、記事、投稿、エンディング分岐、炎上編の文面など）
- 彼の写真セット: Tinder版は現行の私服・IG用が中心。過去編は各サバイバル編リポジトリの時代別公式プロフィールを使う（詳細: `ASSETS_NAO.md` §4）
- UIスキン: Tinder版は2026年現行仕様。本作も全時代でこの現行スキンを共通使用する（時代別スキンは作らない。本人決定 2026-11-09、§3）

## 3. 時代別UIスキン：作らない（本人決定 2026-11-09）

- 当初は時代別スキン（2019=LINE旧UI＋Twitter、2021=WeChat／Weibo風、2023=カカオ風）を必須の新規作業としていたが、本人が「時代スキンはいらない」と決定したため**全廃**。
- 全時代で Tinder版の現行UIスキンを共通使用する。時代の違いは、アプリの見た目ではなく中身（投稿・メッセージの内容、日付、登場人物、番組側の表示）でのみ表現する。
- これにより新規開発は、ループ管理・差分再演・応援台帳・Keepsake・Canon Lock結果画面・0周目リードオンリーモードに集中する。

## 4-0. 番組アプリは流用（新規開発ではない／2026-11-09 本人指摘で確定）

番組アプリ（練習生名簿・順位発表・投票・ミッション表示）は、裏側3部作（『担当をデビューさせる件』各編）に実装済み。本作は時代ごとに流用元を切り替える。

| 本作の時代 | 流用元 | 実在を確認した実装（2026-11-09 実コード確認） |
|---|---|---|
| 2019 日プ編 | `~/workspace/produce-uragawa/`（日プ編） | APPS定義に `members`「練習生名簿」（view `v-members`、S1キャスト写真連動）、`rank`「順位表」（view `v-rank`、順位発表の到達バッジ連動）、`vote`「投票」（view `v-vote`、`voteOpenRound()`／`voteVotedToday()` による日次投票・投票済み管理、ホームのウィジェット連動表示まで実装済み） |
| 2021 創造営編 | `~/workspace/chuang-uragawa/`（創造営編） | APPS定義に `rank`「順位表」（`renderRankApp()`）、`members`「メンバー」（`renderMembers()`、主要学員・メンター）。投票は番組側の仕組みに寄せ「サポート室」アプリが担う構成 |

- 流用方法: 各編の該当 view／render 関数とデータ形式（キャスト・順位データ）を本作の時代パートへ移植し、本作側の差分（主人公本人が名簿に載る、自分の順位表示、Canon Lock結果画面との接続）だけを足す。
- ミッション／課題表示は、3部作では物語ステップと番組アプリ内の表示で担われているため、本作も同じ作法（番組アプリの「お知らせ／ミッション」欄＋物語側の提示）で流用する。

## 4. 新規開発が必要なもの

1. ~~**番組アプリ**~~ → §4-0 のとおり流用に変更。本作側で足すのは「主人公の名簿・順位表示」と Canon Lock 結果画面への接続のみ
2. **ループ管理**: 周回カウンタ、時代×周回の進行管理、ループ開始時の「前回の30秒まとめ」自動生成
3. **差分再演エンジン**: 同一場面の再演時に同一文をグレー表示し、差分行だけハイライトする描画＋「Diff Log」（差分コレクション画面）
4. **応援台帳**: 前の周で成立した応援・救済が次の周の維持義務になるリスト管理（時代ごとに上限2〜3件、2周目は彼と共同維持）
5. **Keepsake Box**: 周を跨いで残る物・言葉の所持品管理（残るかどうかは「彼が残すと決めたもの」だけ、というルール付き）
6. **Canon Lock 結果画面**: 順位発表で「結果は固定／変わったのは中身」の内訳を表示する専用画面
7. **ゲージ基盤**: 違和感／男装バレ度／届いた数／主人公スキル（歌・ダンス）の継承計算（詳細は `DESIGN.md` §5）
8. **0周目リードオンリーモード**: 操作ボタンを持たない放送視聴パートの表示モード
